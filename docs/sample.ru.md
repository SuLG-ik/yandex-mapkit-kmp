# Пример приложения

[Проект-пример](https://github.com/SuLG-ik/yandex-mapkit-kmp/tree/main/sample) — приложение на
Compose Multiplatform, которое прогоняет всю обёртку. Весь код карты в нём лежит в `commonMain`;
проекты Android и iOS только запускают его.

## Как запустить

Для запуска экранов с нативной картой укажите действующий ключ MapKit в `local.properties`.

=== "local.properties"

    ```
    MAPKIT_API_KEY=<API-KEY>
    ```

=== "Android"

    ```bash
    ./gradlew :sample:androidApp:installDebug
    ```

=== "iOS"

    После клонирования запустите `./gradlew :sample:composeApp:podInstall`. Затем откройте
    `sample/iosApp/iosApp.xcworkspace` в Xcode и запустите приложение.

[BuildKonfig](https://github.com/yshrsmz/BuildKonfig) генерирует ключ в общий код — это тот же
приём, что описан в [Быстром старте](getting-started/quick-start.md).

## Что внутри

Приложение открывается меню экранов, каждый из которых покрывает свой срез API.

| Экран | Что показывает |
|---|---|
| **Old api objects** | API контроллера — `MapControllerEffect` и императивный код MapKit, включая кластеризацию |
| **New api objects** | API состояний — `Placemark`, `Circle`, `Polygon`, `Polyline`, `Clustering`, composable-иконки |
| **Layers, listeners and states** | `MapObjectCollection`, `MapObjectLayer`, `TileLayer`, `TrafficLayer`, `MapListeners`, объекты состояния и `traverse` |
| **Storage, offline cache, i18n** | `StorageManager`, `OfflineCacheManager`, `I18nManager` и поток логов MapKit |
| **Return to map** | сохранение камеры и выбранной метки при переходе в детали или на другую вкладку |
| **Measure return to map** | Замер создания карты, присвоения объектов, готовности проекции и загрузки тайлов после инициализации MapKit. Для реальных тайлов нужен отдельный ключ. [Инструкция по замеру](https://github.com/SuLG-ik/yandex-mapkit-kmp/blob/main/verification/return-to-map/README.ru.md). |

В примерах API события выводятся прямо на экран. Нажатие, движение камеры или неудавшийся вызов
можно проверить без отладчика.

Это переписанное на этой библиотеке
[официальное демо Yandex MapKit](https://github.com/yandex/mapkit-android-demo), поэтому одни и те же
сценарии можно сравнивать бок о бок с оригинальным Android-кодом.

## Возврат к карте

Откройте **Return to map** и нажмите красную метку к юго-западу от центра **Tab A**. Убедитесь,
что выбрана `A-1`, слегка сдвиньте камеру и нажмите **Open details**, **Move marker** и
**Back to map**. Камера вернётся к сохранённой области, а зелёная метка с тем же ID окажется
в новой точке. Снова откройте детали, нажмите **Remove marker**, затем **Back to map**.
Выбор очищается, а удалённая метка исчезает.

Сдвиньте камеру и выберите метку на **Tab B**, затем переключитесь между вкладками. У каждой
вкладки своя запись в `rememberSaveableStateHolder` с ID вкладки в качестве ключа. В записи
сохраняются камера, ID выбранной метки и правки каталога. При открытии деталей `YandexMap`
выходит из композиции. При возврате новая карта один раз применяет сохранённую камеру через
`CameraPositionState` и отображает актуальный каталог. Оба провайдера иконок создаются выше
содержимого вкладок и переиспользуются, пока открыт пример. **Exit example** завершает этот
сценарий. При новом входе состояние начнётся с исходного.

При пересоздании хоста реестр сохраняемого состояния может восстановить записи вкладок.
При использовании навигации привяжите состояние к устойчивому ID записи маршрута и удалите
его, когда маршрут окончательно покинет стек. Если выбранная метка или область нужна при новом
запуске без сохранённого состояния интерфейса, запишите значения и ID в своё долговременное
хранилище. Нативные представления, слушатели и объекты карты принадлежат текущему хосту.

### Кеш тайлов и офлайн-регионы

MapKit хранит на диске отдельный временный кеш тайлов. `StorageManager` позволяет узнать размер и
поставить ограничение. При достижении ограничения MapKit удаляет старые тайлы и при необходимости
запрашивает их снова. Попадание в кеш помогает получить данные карты. Камеру и ID выбранной метки
восстанавливает владелец маршрута. Для офлайн-карт скачивайте поддерживаемые регионы через
`OfflineCacheManager`. Загрузка регионов требует платной лицензии MapKit. [Справочник хранилища](https://yandex.com/maps-api/docs/mapkit/com/yandex/mapkit/storage/StorageManager.html) · [Руководство по офлайн-картам](https://yandex.com/maps-api/docs/mapkit/ios/generated/tutorials/map_offline.html)

Изменения в примере проверяются в [GitHub Actions][sample-ci]. В Android-тестах состояния
маршрута вместо нативной карты используется небольшой интерфейс, а для iOS компилируется
цель симулятора. Задачи используют условный ключ. В базовом отчёте описан нативный прогон
Android-примера с касаниями меток, восстановлением камеры после завершения фонового процесса
и сбросом состояния при выходе из примера. [Нативная проверка состояния][return-baseline]

### Как сохранить карту в пределах одного хоста

В примере замеров есть **Details (unmount map)** и **Other tab (retain map)**. Оба сценария
используют одну камеру, тот же набор меток и те же настройки хранения SDK. Во втором случае
карта остаётся в хосте, а касания принимает содержимое поверх неё. Когда владелец карты
окончательно покидает стек, удалите карту и её слушатели вместе с маршрутом.

На каждом симуляторе провели пять серий с реальными тайлами при одном размере окна. На Android
медиана до готовой проекции составила 83 мс после пересоздания карты и 28 мс у сохранённой
вкладки. На iOS — 66 мс и 17 мс соответственно. При повторном открытии создавались одна карта,
три метки и один провайдер иконок. Сохранённая вкладка переиспользовала их на обеих платформах.
Колбэк завершения загрузки тайлов после повторного открытия пришёл через 6,6 секунды на Android
и 0,52 секунды на iOS по медиане. Готовность проекции и завершение загрузки тайлов — разные
этапы. [Данные базовых замеров и условия][return-baseline]

Если маршрут может покинуть хост, сохраняйте камеру и выбор. При коротком переключении вкладок
в пределах одного хоста пример с сохранённой картой показывает, как восстановить доступ к той
же области без пересоздания объектов. Проверьте этот вариант в своём приложении на том же
устройстве и в той же области, включая расход памяти и доставку касаний при перекрытии карты.
