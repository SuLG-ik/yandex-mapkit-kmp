# Замер возврата к карте

[English instructions](README.md)

Откройте в приложении-примере **Measure return to map**. Отдельный пример **Return to map**
показывает сохранение камеры и выделения. На обеих платформах пробник использует
окно 260 dp, дневной стиль, камеру 55.751225 / 37.629540 с масштабом 16, нулевыми наклоном и
азимутом и три локальные метки. Режим **Native view only** не загружает базовую карту.
**Real tiles** использует векторные тайлы и обычный дисковый кеш SDK.

Приложение инициализирует MapKit, пока открыты настройки замера. Отсчёт начинается при
открытии карты. Строка отчёта указывает `scope=post_init`. Запуск процесса, инициализация SDK
и переходы по меню в интервал не входят.

## Прогон Android в GitHub Actions

Когда workflow появится в `main`, запустите **Return-to-map benchmark** вручную на `main`.
Эмулятор Pixel 7 с образом Android 37 Google APIs повторит пять серий. В каждой серии перед
первым замером очищается хранилище. Затем пробник возвращается к пересозданной и сохранённой
карте в том же процессе. Последний замер выполняется после остановки и запуска процесса
с нетронутыми данными. Драйвер находит элементы примера и отправляет настоящее нажатие
в центр карты через 350 мс после обнаружения готовой проекции. Задержка включает обнаружение
подсказки и время доставки ввода.

Приложение собирается с условным ключом. Доверенный запуск получает отдельный ключ после
сборки и запуска эмулятора и передаёт его через stdin в закрытую папку приложения. Debug-версия
считывает и удаляет файл при каждом запуске процесса. Workflow публикует извлечённые строки
метрик и сводку. Для полной серии нужны четыре замера с проекцией и нативным касанием,
подтверждённые тайлы на созданных окнах и ноль новых созданий при сохранении карты.
Для сопоставимого базового замера все пять серий должны использовать одинаковые версию SDK и размер
окна карты. Неполная серия или расхождение завершает прогон ошибкой. Извлечённые строки сохраняются,
а сводка сообщает о расхождении.

Для iOS используйте ручной порядок ниже. В отдельной задаче можно подключить тот же пробник
к существующему хосту MapInteraction XCTest и проверить, что повторный запуск сохраняет
контейнер приложения и кеш.

## Порядок прогона

Используйте отдельную тестовую установку, одну версию приложения и ОС, одно устройство и
портретную ориентацию на отчёт. Для реальных тайлов понадобится отдельный ключ MapKit в
игнорируемом `local.properties` на доверенной машине. Проверки PR компилируют пробник
с условным ключом без сбора замеров. Пустой ключ, условный ключ CI и ключ из нулей дают
`missing_key` при попытке загрузить реальные тайлы. Ключ из нулей годится для замеров без базовой карты.

1. На Android очистите хранилище установленного тестового приложения. На iOS полностью удалите
   приложение и установите снова в пустой контейнер. Выгрузка приложения сохраняет данные.
   Если установки могут делить данные SDK, используйте отдельный тестовый симулятор или
   устройство. Введите анонимный идентификатор серии, например `trial_01`, выберите режим
   и нажмите **Open after clearing app data**. По подсказке один раз коснитесь центра карты.
2. После результата или 30-секундного дедлайна нажмите **Details (unmount map)** и **Return to map**.
   Пробник создаст новое окно карты в том же процессе.
3. После результата нажмите **Other tab (retain map)** и **Return to map**. Карта останется
   смонтированной во время показа вкладки. Повторите касание.
4. Полностью завершите процесс и запустите то же приложение с нетронутыми данными и кешем.
   Введите тот же идентификатор серии и режим, нажмите **Open after process restart** и
   повторите касание. Сохраните строки обоих процессов.

Повторите каждый внутрипроцессный сценарий не менее пяти раз. Для новых холодных замеров
снова очистите хранилище и задайте новый идентификатор серии. Сравнивайте холодные и тёплые
тайлы при одинаковой сети и окне. Холодный прогон с `tiles=loaded` должен предшествовать
тёплому. Сохраняйте и строки с таймаутами.

## Подготовка отчёта

Скопируйте строки `MAPKIT_RETURN_METRIC|` с экрана или извлеките их из локального Logcat
или консоли Xcode параметром `--metrics-out`. Публикуйте только извлечённые строки и сводку.

Для автоматического ввода дождитесь тега `return-map-benchmark-ready`. Отправьте одно
физическое нажатие в центр `return-map-benchmark-viewport` с одинаковой задержкой после
обнаружения тега во всех сценариях. Укажите эту задержку в отчёте вместе с используемым драйвером.

```sh
python3 verification/return-to-map/summarize.py --device "Android Pixel 6a, API 33" --revision YOUR_GIT_SHA --metrics-out android.metrics android-local.log
```

- `mount_ms` и `overlay_ms` отмечают наблюдаемое создание окна и присвоение локальных меток.
  Число созданных окон, меток и иконок также записывается. При сохранении прежних меток
  `overlay_ms=na`. Работа в скрытом окне может увеличить счётчики без отметки времени.
- `ready_ms` — первый наблюдаемый кадр Compose с нужной камерой и рабочей проекцией.
  `tap_ms` подтверждает доставку настоящего касания, включая время реакции человека.
- `tile_ms` отмечает ответ SDK с проверенной камерой и проекцией. Непроверенный ранний
  ответ отдельно отражается в `early_tile_ms`, а `tile_registered` показывает стадию
  постановки слушателя. Сохранившееся окно с нулём новых созданий отмечается `retained`
  после наблюдения проекции. Если нативное окно создалось заново, даже при выборе сохранения,
  пробник ждёт ответ о тайлах.

Сводка показывает число попыток по сериям, медиану, диапазон и число наблюдений для каждой
величины. Сводка по маршруту учитывает все попытки одного сценария. Для подтверждённых метрик
тайлов есть отдельные таблицы по стадиям `mount` и `ready`. Знаменатель каждой таблицы включает
попытки со своей стадией, в том числе таймауты. Ранние неподтверждённые ответы входят в сводку по
маршруту, поскольку в строке записана последняя стадия регистрации. Перепроверяйте вклад
загрузки тайлов по `tile_ms - ready_ms` в связанных сериях с одинаковой стадией постановки
слушателя. Изменение задержки может указывать на работу кеша.
SDK не сообщает попадание в кеш для каждого тайла. Замеры выполнения на обеих платформах
ещё нужны для [#74](https://github.com/SuLG-ik/yandex-mapkit-kmp/issues/74).
